# T1218.011: System Binary Proxy Execution (Rundll32)

**Tactic:** Defense Evasion | **ATT&CK:** https://attack.mitre.org/techniques/T1218/011/

## Why it matters
`rundll32.exe` is a signed Windows binary that can load arbitrary DLLs, so attackers use it to run malicious code under a trusted process name (a "living off the land" technique).

## Simulation
```powershell
rundll32.exe shell32.dll,Control_RunDLL
```
This opens the Control Panel, which is benign, but it uses the same execution pattern as abuse.

## Before: the gap
Sysmon logged the event locally (confirmed in Event Viewer), and the agent was shipping other events, but nothing appeared in Wazuh Discover because no default rule matched.
Evidence: `evidence/T1218.011-before-zero-hits.png` (`rule.id: 100002` returns 0 hits)

## Detection: custom rule 100002
```xml
<rule id="100002" level="8">
  <if_group>sysmon_event1</if_group>
  <field name="win.eventdata.image">rundll32.exe</field>
  <description>Rundll32.exe execution detected (potential LOLBin abuse)</description>
  <mitre><id>T1218.011</id></mitre>
</rule>
```
- **Level 8 (lower than 100001):** rundll32 runs constantly in normal Windows use, so this is a visibility rule, not a high-confidence alert.

## After: validated
Re-running the command produced 1 hit for `rule.id: 100002`.
Evidence: `evidence/T1218.011-after-alert.png`

## False positives
High. Windows and many applications call rundll32 routinely.

## Gaps and tuning ideas
- Alert on suspicious arguments instead: DLLs loaded from user-writable paths (`%TEMP%`, `AppData`), `javascript:` or `http` in the command line, or unusual parent processes (Office apps, scripting hosts).
- Treat this rule as a hunting aid and build higher-severity child rules on top of it.
